# 技术架构与关键决策

## 产品边界

药小伴是私人记录工具，不是医疗服务。系统只对用户确认的时间、数量和日期执行确定性计算，不判断用量是否正确，也不决定是否续用、停用、换药或购买。

## 运行模式

### 本机演示模式

当运行模式显式设为 `demo` 且 `cloudEnvId` 为空时，应用使用 `LocalDataService` 和小程序本地存储，目的是让隔离的自动化工程在不访问生产数据的情况下完成交互验收。设置页应明确展示演示模式。清除开发者工具缓存会删除全部演示数据；正式构建禁止静默回退到此模式。

### 正式云模式

填入 `cloudEnvId` 后，应用只调用 `medicine-api` 云函数。网络或云配置失败时返回明确错误，不回落到本地数据，防止同一用户形成两个互不一致的药箱。

## 数据流

```text
页面输入
  → 客户端字段校验
  → DataService（本机或云端适配）
  → 服务端身份/版本/幂等/所有权校验
  → CloudBase 私有集合
  → AppState DTO
  → 纯领域函数生成今天任务、风险和预计余量
```

所有写操作具有稳定 `requestId`；更新同时带 `expectedVersion`。服务端不接受客户端传入的 `OPENID` 或 `accountId` 作为身份依据。

## 预计库存语义

最近一次 `InventorySnapshot` 是唯一实际库存基线。此后：

- 已发生且未标记“未服”的固定计划默认计入预计消耗。
- “已服”仅确认事实，不再次扣减。
- “未服”排除相应计划消耗。
- “额外使用”单独扣减一次。
- 撤销记录会恢复默认计划语义。
- 新盘点覆盖此前估算误差，但保留历史日志。
- 预计值最低显示为零，首次不足单独显示。
- 按需使用、没有盘点或没有固定计划时不虚构用完日期。

计划按版本存储。`effectiveFrom <= scheduledAt < effectiveTo`，修改计划不会重写历史。

## 系统日历

每个实际提醒时间生成一个稳定事件键，键包含计划、写入窗口、标题隐私模式、星期和时间。写入窗口从“上海今天”和计划开始日中较晚者起算，最长 90 天。

多事件逐条写入并逐条持久化成功结果；部分失败重试时只补未成功事件。由于微信没有系统日历查询/修改/删除接口，数据库中的状态只能表达“曾请求并成功写入”，不能证明事件仍存在。

## 安全边界

- `medicine-api` 只处理带小程序身份上下文的交互请求。
- `reminder-worker` 只处理定时任务，不读取 `getWXContext()`，避免实例复用导致身份残留。
- 客户端数据库权限全部关闭。
- 日志只记录操作类型、请求 ID、错误码和时延，不记录药名、剂量、备注或导出内容。
- 进入后台时通过 `visualEffectInBackground: hidden` 隐藏页面。
