# 商用发布检查清单

## 自动化门禁

- [ ] `npm ci` 成功。
- [ ] `npm run verify` 全绿。
- [ ] 微信开发者工具编译无错误、警告已逐项解释。
- [ ] 领域逻辑行/函数覆盖率达到约定门槛。
- [ ] `git diff --check` 无空白错误。

## 核心旅程

- [ ] 首次隐私同意前无健康数据写入。
- [ ] 只记药名和月精度有效期可在 45 秒内完成。
- [ ] 完整固定计划可在 2 分钟内完成。
- [ ] 每天与指定星期计划边界正确。
- [ ] 不打卡仍按计划估算；已服不二扣；未服排除；撤销恢复；额外使用扣一次。
- [ ] 重新盘点后从新基线计算，预计值不为负数。
- [ ] 按需药、无盘点和无计划不生成虚假用完日期。
- [ ] 修改计划不重写历史，并立即使旧日历账本失效。
- [ ] 空、加载、网络、冲突、权限拒绝和保存失败状态均有明确文案。

## 隐私与安全

- [ ] 公众平台隐私保护指引与实际 API 完全一致。
- [ ] 单独同意、隐私政策、导出和两步删除通过审核。
- [ ] 数据库集合客户端读写全部关闭。
- [ ] 两个真实微信账号的跨账号访问为零。
- [ ] 生产日志、错误上报和 URL 不包含药名、剂量、备注或导出内容。
- [ ] 账号删除后立即不可访问，活动数据 24 小时内清理。
- [ ] 后台视觉内容已隐藏，日历标题默认不暴露敏感信息。

## 真机日历

- [ ] iOS、Android 各至少两种常见屏幕宽度。
- [ ] 允许、拒绝、永久拒绝、接口失败、部分成功和重试。
- [ ] 每天多个时间、指定多个星期、计划提前结束和 90 天窗口。
- [ ] 重复点击不会在当前账本生命周期内重复写入。
- [ ] 编辑、停用、归档和账号删除均显示旧事件手动清理提示。
- [ ] 产品不声称能查询、同步或删除系统日历事件。

## 微信订阅消息

- [ ] 模板 ID 与字段映射经过真实模板校验。
- [ ] `accept/reject/ban/filter` 均有降级路径。
- [ ] 一次性授权发送一条后才消费额度，发送失败不错误消费。
- [ ] 同一用户串行发送，任务抢占和重试幂等。
- [ ] “服务端受理”不显示为“用户已收到”。
- [ ] 模板不可用时站内风险卡片完全正常。

## 无障碍与体验

- [ ] 点击目标不少于 88×88rpx，正文不小于 28rpx。
- [ ] 200% 系统字体下无截断、重叠或不可达按钮。
- [ ] VoiceOver/TalkBack 完成首次同意、添加、计划、记录、盘点、日历、导出和删除。
- [ ] 状态不只依赖颜色，所有图标按钮有中文可读标签。
- [ ] 10–20 名未参与设计的目标用户完成 45 秒/2 分钟可用性测试。

## 审核与运营

- [ ] AppID、服务类目、备案和主体信息已确认。
- [ ] 页面、截图和审核说明统一使用“记录、预计、提醒”，不出现诊断或推荐承诺。
- [ ] 提供审核账号、完整体验路径和测试数据。
- [ ] 隐私政策已补充真实运营主体、联系方式和第三方清单。
- [ ] 已配置错误率、保存成功率、任务延迟、删除 SLA 和越权告警，且不采集药品内容。
