# 微信开发者工具交互验收

`journeys.mjs` 通过微信官方 `miniprogram-automator` 驱动已安装的微信开发者工具。它验证的是真实页面、本地数据服务和业务导航，不使用 mock 代替业务结果。每次运行都会从当前生产构建生成仓库内隔离且被 Git 忽略的 `.e2e-project` 演示工程：保留正式 AppID 以兼容当前 Nightly 工具，但把运行模式显式改为 `demo` 并清空云环境 ID，因此不会调用或改写生产 CloudBase 数据。

## 前置条件

- macOS 已安装微信开发者工具，CLI 路径为 `/Applications/wechatwebdevtools.app/Contents/MacOS/cli`
- 根项目已安装 `miniprogram-automator@0.12.1`
- 根项目可以完成正式构建；测试脚本会重建 `.e2e-project`
- 开发者工具没有被另一个自动化会话占用
- 当前 Nightly 工具需要在每个脚本启动的隔离窗口中点一次“编译”；脚本会在等待页面就绪时保持运行

## 运行

```bash
node tests/e2e/journeys.mjs
```

脚本会自动选择可用端口，并为两条旅程分别启动一个干净的开发者工具窗口。也可以指定第一条旅程的起始端口：

```bash
E2E_PORT=9433 node tests/e2e/journeys.mjs
```

脚本会清空微信开发者工具模拟器中本项目的本地存储，然后验收：

1. 首次启动、勾选并同意隐私说明。
2. 新增一个“只记效期”的药盒，验证填写数量时必须显式选择单位，再进入详情、盘点数量并从药箱回访。
3. 按运行时间动态新增每日固定计划，验证“仅可提前 10 分钟记录”的界面和服务两层限制，再记录“已服”并撤销。
4. 归档计划药盒，验证恢复后只继续管理有效期、不重启旧计划；再次归档后永久删除，并确认计划、盘点、服药记录和日历导出数据全部级联清理。

## 验收边界

该脚本不将以下项目标记为已通过：

- 真实 AppID 登录、云环境、`OPENID` 隔离和跨设备同步。
- iOS/Android 真机系统日历权限及事件写入。
- 订阅消息真实模板和到达。
- 微信后台上传、审核和发布。

这些项目需要真实主体账号、生产云环境、模板 ID 或真机权限；隔离 `demo` 工程的通过不能替代真实环境验收。
